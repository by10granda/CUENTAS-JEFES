# Mocked Browser Tests

Install Chromium with `npx playwright install chromium`, then run `npm run test:e2e`. The config starts Vite at http://localhost:5173 or reuses an existing development server there. No API process is required because all API responses are intercepted. If you use a custom browser install directory, set `PLAYWRIGHT_BROWSERS_PATH` to that directory when installing and running tests.

These tests exercise the real frontend with intercepted `/api/index` responses using the documented API envelope. Public config is mocked as `{authMode: 'password', configured: true/false}` without credentials; sessions use `{username, name}`. They are not live password-authentication, backend, Sheets, or Drive integration tests and need no real credentials. Unexpected API actions and external requests fail the tests.

Google Fonts CSS is intercepted with an empty stylesheet so tests use local fallback fonts without network access. Login uses test-only shared username/password fixtures and intercepted responses; no Google login scripts or Google Cloud configuration are needed. Passwords and secrets for the real application belong only in private server variables, never Sheets, frontend configuration, or chat.

The default bootstrap contains only approved catalogs, with empty accounts and movements. Account creation explicitly supplies a zero opening balance. Income, expense, and payment amounts exist only in opt-in synthetic fixtures under this directory and are never written to production services.

Both desktop and mobile Chromium run setup-warning, password-login, empty-dashboard, account/movement retry, linked-payment accounting, and actual XLSX/PDF download checks. Login checks retain failed credentials, clear the password on success, and ensure it is not stored in browser storage; drafts are keyed by username. Screenshots and traces are retained on failure. Downloads and runner artifacts are generated under `e2e/test-results/`.

Latest agent-reported results are 12 browser tests passed (six scenarios on desktop and mobile) and 38 unit/HTTP tests passed. The main agent will rerun final verification; this documentation edit does not claim a new test run or live financial integration. The existing https://cuentas-jefes.vercel.app public web/API was previously checked; the new login deployment is pending push/deploy, and protected Sheets/Drive operations remain unvalidated in vivo.

The public link intentionally admits anyone with the shared credentials the owner will configure later. Audit records use that shared username, not per-person attribution, and historical audit emails are preserved. Before connected testing, update the remote Apps Script `doPost` identity validation and all five write invocations from email to username, then republish **Nueva version** at the same `/exec` URL; see the exact changes in the root README. This identity-only migration does not change the field schema or require a setup reset. Public `/exec` GET always denies access by design.

Browser mocks do not prove resistance to brute force. No distributed lockout or application-level password-attempt limit is implemented; the public login endpoint permits repeated attempts. Configure and verify Vercel firewall/rate limiting for both login routes before real production, rather than treating these tests as evidence that this protection exists.
